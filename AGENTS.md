# AGENTS.md

## Project Purpose

This project generates and serves a local news radar website from daily digest files under `digests/`.

The browser UI is static. It loads:

- `/manifest.json` to discover available dates.
- `/digests/<date>/news-data.json` to render the selected date.
- Local browser vendor scripts from `/assets/vendor/`.

This is a fully local project. Do not assume GitHub Pages, GitHub Issues, remote deployment, notification bots, or any online publishing workflow unless the user explicitly asks for a new deployment design.

## Common Commands

- Generate daily news data and manifest: `pnpm daily`
- Regenerate only manifest/feed: `pnpm manifest`
- Serve the site on the LAN: `pnpm serve`
- Type-check TypeScript source: `pnpm typecheck`
- Run tests: `pnpm test`

Script entry points live under `src/cli/`. Keep package scripts pointing at those files.

`pnpm serve` must listen on `0.0.0.0:3000` so other devices on the same LAN can open `http://<host-ip>:3000/`.

If users cannot see the page, first verify:

- The server process is actually listening on port `3000`.
- `/manifest.json` returns `200` from the shared URL.
- `/digests/<date>/news-data.json` returns `200` from the shared URL.
- Windows Firewall allows inbound TCP traffic on port `3000`.

## Frontend Structure

- `index.html`: static document shell and semantic layout only.
- `assets/css/news-radar.css`: all page styling.
- `assets/js/app.js`: app state, routing, event binding, and bootstrapping.
- `assets/js/data-loader.js`: JSON loading from static resources.
- `assets/js/renderer.js`: DOM rendering and event wiring for rendered fragments.
- `assets/js/config.js`: section order, storage keys, and labels.
- `assets/js/utils.js`: shared DOM, escaping, markdown, and storage helpers.
- `assets/vendor/`: local browser builds of third-party libraries required by the page.

Keep these responsibilities separate. Do not move data fetching into render functions, and do not put large scripts or CSS back into `index.html`.

## TypeScript Source Structure

- `src/cli/`: executable entry points used by `package.json` scripts.
- `src/collectors/`: news RSS/source fetching and normalization.
- `src/reports/`: LLM calls and prompt builders used by the news pipeline.
- `src/shared/`: date utilities and localized labels/messages.
- `src/providers/`: LLM provider implementations and provider factory.
- `src/__tests__/`: Vitest tests for source modules.

Keep entry points thin when practical. Put reusable fetch logic in `src/collectors/`, report/prompt logic in `src/reports/`, and cross-cutting utilities in `src/shared/`.

## Data Structure

Daily news output lives in `digests/YYYY-MM-DD/`.

Required for the website:

- `news-data.json`: structured payload used by the browser UI.
- `news-*.md`: markdown reports used by RSS/feed generation and archive data.
- `highlights.json`: local highlight payload shown or reused by local tooling.

`manifest.json` is generated by `src/cli/generate-manifest.ts`. It lists dates that have `news-*` markdown reports. If a date is missing from the UI, regenerate the manifest first.

## Editing Rules

- Preserve current behavior unless the user explicitly asks for behavior changes.
- Prefer structure-only changes when improving readability.
- When moving files, update imports and tests only; avoid mixing behavior changes into pure structure work.
- Keep frontend requests using paths relative to `document.baseURI` (e.g. `manifest.json`, `digests/<date>/news-data.json`) so the site works both at LAN root and at the GitHub Pages project subpath `/news_radar/`.
- Keep vendor scripts local so LAN users do not depend on external CDNs.
- Do not add fallback data into `index.html`; fix the source data or serving path instead.
- Do not add GitHub Issues, GitHub Pages, Telegram, Feishu, social posting, finance, AI-tool digest, weekly, or monthly legacy workflows back into the project without explicit approval.
- Do not use `git add -A` casually because `digests/` often contains generated or removed files.
- Run `pnpm typecheck` and `pnpm test` after source tree restructuring.

## Troubleshooting LAN Sharing

Use the exact host IP, not `localhost`, for other devices:

```text
http://<host-ip>:3000/
```

From the host machine, verify the same URL that other users use:

```powershell
Invoke-WebRequest -Uri "http://<host-ip>:3000/manifest.json" -UseBasicParsing
Invoke-WebRequest -Uri "http://<host-ip>:3000/digests/2026-06-03/news-data.json" -UseBasicParsing
```

If `pnpm serve` reports a random port, port `3000` was already occupied. Stop the old process and restart `pnpm serve`.
